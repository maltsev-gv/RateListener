# Features Plan — RateListener

Цель: починить сломанную функциональность, добавить трей с уведомлениями, график истории,
гибкий опрос провайдеров и фоновый режим. Статическую архитектуру не трогаем (отдельный этап).

Границы: без локализации, без кросс-банковских цепочек, без рефакторинга статики.
Валидация каждой фазы: `dotnet build RateListener.sln` + ручной прогон сценария из пункта «Проверка».

---

## Фаза 1. Исправления

### 1.1 Индикатор изменения курса (колонка Change)
- `ViewModels/ListenerSettingsViewModel.cs`: хранить `previousEffectiveRate` (перезаписывается после каждого успешного пересчёта; сброс при смене валют/банка — рядом с логикой `prevCurrencies`).
- Новые свойства: `ChangeValue` (double, разница), `ChangeDisplay` (`↑ +0.15` / `↓ −0.20`, пусто до второго обновления).
- `OverviewWindow.xaml`: колонка Change биндится на `ChangeDisplay`; цвет через существующий `IsNumberNegativeConverter` или DataTrigger (зелёный/красный). ToolTip — предыдущее значение и время.
- Не персистим: индикатор сессионный.

### 1.2 Отписка удалённых листенеров
- `ViewModels/ListenerSettingsViewModel.cs`: метод `Unsubscribe()` → `OverviewViewModel.RatesUpdated -= UpdateUi`.
- `ViewModels/OverviewViewModel.DeleteListener`: вызвать перед `Listeners.Remove`.

### 1.3 Валидация порогов алертов — ValidatedTextBox
- Новый `Controls/ValidatedTextBox.xaml(.cs)` (UserControl, внутри TextBox).
- DP: `Text`, `ValidateFunc` (Func<string,bool>). Ввод не блокируется никогда; невалидное значение → оранжевая рамка (`BorderBrush=Orange`, толщина 1–2).
- Правило для порогов: пусто допустимо только при выключенном чекбоксе порога — но проверка рамки чисто визуальная, VM не меняется.
- Применить к `AlertWhenMore` / `AlertWhenLess` в `OverviewWindow.xaml`. Позже опционально — к `FromFee`/`ToFee`/суммам.

### 1.4 Устойчивость парсинга BccStableProvider (и паттерн для остальных)
Предложения:
1. Null-guard: `SelectNodes(...)` может вернуть null → возвращать `RatesResponse { Success=false }`, не падать.
2. Fail-loud на пустом результате: 0 распознанных пар при валидном HTML = `Success=false`, message «layout changed: 0 pairs parsed» (сейчас молча пустой список выглядит как «нет данных»).
3. При неудаче сохранять последний HTML в `%TEMP%\RateListener\BccStable_last_failed.html` для отладки селекторов.
4. Опционально: запасной набор XPath-селекторов (основной/резервный), чтобы мелкие правки вёрстки не ломали провайдер.
Тот же паттерн (guard + fail-on-empty) распространить на CifraBank/Ffin при ревизии.

### 1.5 Открытие ссылки
- `ListenerSettingsViewModel.OpenLinkMethod`: заменить cmd-хак на
  `Process.Start(new ProcessStartInfo(url) { UseShellExecute = true })`; guard на пустую ссылку.
- Проверка: `dotnet build`; вручную — добавление/удаление листенера, клик по ссылке, клик по Rate.

## Фаза 3. Модалка динамики курса

- Триггер: клик по ячейке Rate или Change в списке → модальное окно `RateHistoryWindow`.
- Данные: `ConfigHelper.LoadSettings` уже читает `rates.json` → `DirectionInfo.Rates` (Time строка `dd.MM.yyyy HH:mm:ss`, Rate/InversedRate строки). Парсер tolerant к пробелам-разделителям (`RateToDisplay(true)` форматирует с пробелами).
- Селектор диапазона: День / Неделя / Месяц / Год.
- Пропуски НЕ соединять: сортировать точки по времени, резать линию на сегменты, если разрыв больше порога диапазона (День→1ч, Неделя→6ч, Месяц→1сут, Год→7сут; константы в одном месте).
- Реализация графика: **LiveCharts2** (решено) — оси/тултипы из коробки; разрывы через null-точки или отдельные серии.
- Чекбокс Direct/Inversed — показывать обе линии или переключатель (InversedRate уже хранится).
- Проверка: на истории с заведомыми пропусками линия разрывается; диапазоны фильтруют точки корректно.

## Фаза 4. Интервал опроса по провайдерам

- Хранение (решено): поле `PollIntervalMin` (double, минуты) в `Models/SettingsInfo.cs`; зеркальное свойство `PollIntervalMin` в `ListenerSettingsViewModel` (GetVal/SetVal + StoreSettings; Mapster замапит по имени без конфигурации).
- UI: поле «interval, min» в панели выбранного листенера рядом с комбобоксом банка; дробные значения допустимы (0.5), валидация тем же ValidatedTextBox.
- Дефолты: при добавлении листенера / смене банка проставлять 0.5 для BccFx/BccStable, иначе 10 (решено). Пустое поле = 10.
- Эффективный интервал провайдера = минимум по всем листенерам этого банка (если один банк в двух листенерах — опрашивается чаще).
- Логика: глобальный DispatcherTimer тикает раз в 15 секунд (было 1 мин — укоротить ради интервала 0.5 мин); `FetchAllRatesAsync` берёт только провайдеров, у которых `now − lastFetch ≥ interval`. `LastFetch` — статический словарь в `OverviewViewModel`/`CacheHelper`.
- Кнопка Update — принудительный опрос ВСЕХ провайдеров вне интервалов (решено).
- Проверка: при интервале Ffin=10 между его запросами проходит 10 минут; BCC обновляется каждую минуту.

## Фаза 5. Последнее известное значение при ошибке

- `Helpers/CacheHelper`: хранить на провайдера пару `lastGoodResponse` + `lastErrorResponse` (успешный ответ НЕ затирается неудачным).
- `ListenerSettingsViewModel.UpdateUi`: Rates строятся из `lastGood` всегда; `ErrorMessage` («Parsing error») рисуется в колонке Rate как сейчас; ToolTip ячейки — `{ErrorMessageFull}` + «last value received at {lastGood.Received}».
- Проверка: сломать URL провайдера → таблица показывает старые курсы + красную пометку; время в тултипе соответствует последнему успеху.

## Фаза 7. Автозапуск и фоновый режим

### 7.1 Галка автозапуска
- Хранение (решено): без нового файла — источник истины сам ключ реестра `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`: галка добавляет/удаляет запись с путём текущего exe (+ `/background`, см. 7.2); состояние чекбокса читается из фактического наличия ключа при старте.
- UI: пункт в меню трея + чекбокс в окне (место — рядом с прочими настройками приложения).

### 7.2 Фоновый режим (вместо отдельного сервиса на первом этапе)
- Аргумент командной строки `/background` (или `/minimized`): старт сразу в трей, окно не показывать.
- Ярлык автозапуска создаётся с этим аргументом.
- Обоснование: отдельный Windows Service сейчас невозможен без выноса ядра (провайдеры+расчёт цепочек завязаны на WPF ViewModel и статику `ConfigHelper`/`CacheHelper`); сервис в session 0 всё равно не может показывать уведомления. Реальный сервис — отдельный этап ПОСЛЕ рефакторинга ядра (вынести провайдеры и расчёт в библиотеку без WPF, решить конкуренцию за rates.json между процессами).
- Проверка: перезагрузка → процесс висит в трее, данные собираются, балуны приходят.

## Решения (ранее открытые вопросы)

1. График — **LiveCharts2**.
2. Абсолютно-пороговый алерт «курс пересёк X» — **не делаем**, остаётся текущее поведение (порог как условие при improvement/depreciation).
3. Интервалы: дефолты BCC=0.5 / прочие=10 мин; хранение в `SettingsInfo` (решено, см. Фазу 4); Update = принудительный опрос всех провайдеров.
4. Сервис: сейчас фоновый режим `/background` + автозапуск; настоящий Windows Service — после рефакторинга ядра.

## Порядок работ

Фаза 1 → 5 → 4 → 2 → 7.1 → 7.2 → 3 → 6. (Сначала багфиксы и устойчивость, затем инфраструктура уведомлений, график — самым последним, он самый крупный UI-кусок.)
